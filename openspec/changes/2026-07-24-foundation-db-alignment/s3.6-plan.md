# S3.6 执行方案 · 下线 init_db() 建表职责

**目标**：建表/schema 真相源唯一化为 Alembic。移除 `database.py` 的 `SCHEMA` 常量 +
`init_db()` + `_migrate()` 三块过渡期代码；两条遗留数据规整（planning→backlog、
archived→done）落成 Alembic 002 数据迁移。保留 `get_connection()`（仍被 ~20 个遗留
probe + QA 套件用于 seed 造数）。

## 背景确认（已核查）

- `init_db()` 生产唯一调用点：`main._startup:95`，其**前一行**（:93）已先跑
  `run_migrations()`（Alembic 001）。in-code 注释已称 init_db 为「过渡期双保险，不再
  承担建表真相源」。
- **WAL 不丢**：Alembic `migrations/env.py:88-89` 已用独立 AUTOCOMMIT 连接执行
  `PRAGMA journal_mode=WAL`，全新库仅走 Alembic 也落 WAL；`get_connection()`/engine
  每条连接再断言一次 WAL/busy_timeout/foreign_keys。S1 保证不回退。
- `_migrate()` 全部列补（git_url/is_leader/priority/parent_task_id/nickname/avatar/
  origin/is_dir/downloadable/author_slug/author_name/tool*/attempts/next_retry_at/
  task_run_id/source_run_id/source_message_id/run_id/fail_reason）+ run_events 建表，
  **均已在 001 基线**。唯一非 schema 逻辑 = 两条 status UPDATE（数据规整）。
- `get_connection()` **非死代码**：QA 套件 + lineage/scheduling/rate_limit/orphan 等
  ~20 个遗留 probe 仍用它 seed。**保留不动**。

## 改动清单

### 1) 新增 `backend/migrations/versions/002_normalize_legacy_task_status.py`
- `revision='002'`, `down_revision='001'`。
- `upgrade()`：
  ```
  UPDATE tasks SET status='backlog' WHERE status='planning'
  UPDATE tasks SET status='done'    WHERE status='archived'
  ```

  用 `op.execute(...)`（参数化非必需，值为字面量常量）。
- `downgrade()`：不可逆（旧值已丢失语义），写 `pass` + 注释说明（数据规整不做反向，
  与「planning/archived 状态已废弃」一致）。

### 2) `backend/database.py` —— 移除三块
- 删 `SCHEMA = """..."""` 常量（23–221 行）。
- 删 `async def init_db()`（228–237）。

- **保留** `get_db_path()`、`get_connection()`（及其 import：aiosqlite/load_settings）。
- 清理仅被上述三块使用的 import（若有）。

### 3) `backend/main.py` —— 启动序列
- 删 `from database import init_db`（:15）。
- 删 `await init_db()`（:95）。
- 更新 :89–92 注释：schema 唯一由 Alembic 定义，不再提 init_db 双保险。
- `run_migrations()` 调用（:93）不动 —— 现在它是**唯一**建表路径。

### 4) `TestReport/run_qa_suite.py` —— bootstrap_backend
- 删 `await database.init_db()`（:186）。

### 5) 直接调 `init_db()` 的 probe（5 个）改走 `run_migrations()`
- `run_s34_batch2_probe.py` / `run_s34_batch3_probe.py` / `run_s34_crosspath_probe.py`
  / `run_s34_memory_sync_probe.py`：`await database.init_db()` → `run_migrations()`
  （与 batch4–11 已用的建库方式统一）。
- `run_dialect_helper_probe.py`：同上。

### 6) 语义型 probe 改判（2 个，断言目标从 init_db 换到 run_migrations）
- `run_orm_engine_probe.py`：S1 建库路径 `init_db()` → `run_migrations()`；PRAGMA 断言
  改为「run_migrations 后库处 WAL + get_connection 三条 PRAGMA 一致」。逐条断言不变，
  仅换建库入口。
- `run_wal_concurrency_probe.py`：check「init_db leaves DB in WAL」→「run_migrations
  leaves DB in WAL」；其余（get_connection WAL/busy_timeout、并发无 locked、
  aiosqlite 仅限 database.py）不变。**注**：其中一条 check 断言「database.py 恰有 2
  个 connect 点（init+factory）」——下线 init_db 后变 1 个（仅 get_connection），
  该断言同步改为 1。

## 风险与回滚

- **风险低**：生产早已 Alembic-first，init_db 是空操作；下线是删冗余，无行为变更。
- **唯一行为变化**：两条 status UPDATE 从「每次启动都跑」变为「002 迁移跑一次」。
  语义等价（幂等：规整后无 planning/archived 行，再跑也是空更新）。
- **回滚**：`git revert` 本提交即恢复 init_db；002 迁移 downgrade 为 no-op（数据规整
  不反向，符合状态废弃语义）。
